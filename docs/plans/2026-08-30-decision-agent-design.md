# Mark 通用决策 Agent 设计

## 目标

让 Mark 从“收录和检索资料”升级为“基于团队证据帮助做决策”的通用 Agent。它不限于软件选型，也能处理产品、运营、技术方案等决策问题。

成功的回答必须：

- 给出明确的推荐和备选方案，不停留在泛泛摘要。
- 说明适用条件、主要风险、未知信息和下一步动作。
- 每个重要结论都能回到实际读取过的来源。
- 优先使用团队资料和真实使用经验，证据不足时自动联网补充。

## 飞书交互

用户直接描述目标，例如：

> 公司想做海外社媒监测，预算每月 3000 元，帮我选一个方案。

Mark 先提取决策目标、预算、时间、硬性条件和偏好。只有在缺少会直接改变结论的条件时才追问，且最多追问一次；其他条件合理推断，并在结果中列出假设。

处理期间，Mark 原地更新同一张进度卡片：

```text
理解需求 -> 检索内部资料 -> 联网补充 -> 比较候选 -> 形成建议
```

最终卡片包含：

- 推荐方案和一句话结论。
- 2 至 5 个候选方案对比。
- 预算、功能、安全、部署等条件的满足情况。
- 推荐理由、主要风险、未知信息和下一步建议。
- 团队资料与外部来源。
- `调整条件`、`继续深挖`、`换一批方案`、`保存决策` 操作。

## Agent 循环

现有 Planner 只负责判断消息是否为决策任务。进入决策任务后，交给独立的 Decision Agent 循环，由它根据当前证据决定下一步，而不是执行固定工作流。

首版工具：

| 工具 | 职责 |
|---|---|
| `search_knowledge` | 检索 Mark 资料库、分享信息和团队评价 |
| `search_web` | 根据还缺失的证据搜索外部候选 |
| `read_source` | 读取官网、GitHub、文章或视频的实际内容 |
| `ask_clarification` | 缺少关键条件时追问一次 |
| `compare_candidates` | 动态生成比较维度并检查条件 |
| `save_decision` | 保存结论、证据、参与人和时间 |

每一步后，Agent 检查候选是否足够、关键条件是否有证据、来源是否矛盾，以及是否能形成可执行的结论。默认最多执行 6 至 8 步，深入读取 3 至 5 个最相关候选。

## 数据流与存储

```text
飞书问题
    -> Planner 识别决策意图
    -> Decision Agent 构建需求与评价标准
    -> 内部知识检索
    -> 外部搜索与来源阅读
    -> 证据汇总与候选比较
    -> 飞书决策卡片
    -> Mark 决策中心
```

新建一份独立的“Mark 决策中心”飞书文档。现有资料库回答“我们知道什么”，决策中心回答“我们为什么这样选”。

每个决策记录：问题、发起人、时间、需求与约束、比较标准、候选方案、证据、推荐结论、风险、下一步和状态。状态为 `研究中`、`已建议`、`已采用`、`已放弃` 或 `需要复盘`。

决策记录可以自动保存。联网搜索发现的资料只作为本次决策的临时证据，用户点击“收录这些资料”后才进入长期资料库。

## 证据与评价

不使用一个看似精确的总分代替判断。每个候选在每个条件下标记为 `满足`、`部分满足`、`不满足` 或 `未知`，同时显示证据覆盖度。

来源优先级为：

1. 团队真实使用经验。
2. 官方产品资料与技术文档。
3. 独立测评和可验证的案例。
4. 社区讨论与个人观点。

来源相互矛盾时并列呈现，不在没有理由时自动选择一方。重要来源保存 URL、标题、发布者、抓取时间和支持的具体结论。

## 隐私边界

自动联网前，Mark 先生成脱敏搜索词，只保留产品类别、公开技术要求和预算范围。不向外部搜索服务发送：

- 公司名称、成员姓名和内部项目名。
- 私有链接、服务器地址、密钥和文档原文。
- 被识别为凭据、个人数据或其他敏感信息的内容。

对含敏感信息的问题，Mark 仍可联网，但只使用抽象后的公开需求。

## 错误处理

- 单个网页无法访问时，保留已获得证据，继续阅读其他来源。
- 搜索或 LLM 服务超时时，使用已获得证据降级完成，并显示证据缺口。
- 关键事实无法验证时，返回“暂不能给出可靠结论”，不猜测。
- 达到步骤、时间或费用上限时，使用当前最好证据结束，并说明未完成的研究。
- 写入决策中心失败不影响飞书回答，卡片中提示未保存，允许重试。

## 验证与测试

至少覆盖以下场景：

- 一般决策问题能被正确识别，普通问答不会误进入 Decision Agent。
- 缺关键条件时只追问一次，回答后能继续原决策。
- 每个重要结论都绑定实际读取的来源，不会引用只出现在搜索结果里的摘要。
- 脱敏搜索词不包含密钥、内部名称、私有 URL 或服务器地址。
- 搜索、来源阅读、LLM 或飞书写入任一失败时能正确降级。
- 飞书卡片的调整、深挖、换方案和保存操作作用在正确的决策上。
- 决策保存后，可以基于当时证据回答“为什么选它”和“为什么没选另一个”。

## 首版非目标

- 不自动执行采购、付款、签约、部署或删除等高影响动作。
- 不为每个决策创建独立飞书文档。
- 不在未经确认时把联网结果大量写入长期资料库。
- 不用单一数字分数取代条件、证据和风险说明。
